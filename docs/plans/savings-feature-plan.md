# 저축 기능 기획서

- 작성일: 2026-10-17 (한국 시간)
- 대상: Day To Us 모바일 웹 / PWA
- 상태: 구현 전 기획. 코드·DB·배포 변경 없음.
- 목적: 공동 생활비의 수입·지출과 저축을 구분하면서, 정기 적금과 자유 저축의 월별 납입 및 누적 현황을 관리한다.

## 1. 합의한 방향

1. 저축을 가계부의 하위 탭이 아닌 **가계부·저축·일정과 같은 계층**에 둔다.
2. 저축 기본 화면은 목록이며 월별 조회를 제공한다. 달력도 유지한다.
3. 달력에서 저축을 별도 색상의 점으로 표시하고 날짜 선택 시 기존 하단 drawer로 내역을 확인한다.
4. 저축 색상은 청록색 `#0D9488`, 강조 배경은 `#F0FDFA`를 사용한다.
5. 미래 납입 예정은 빈 점, 반영된 납입 기록은 채운 점으로 구분한다. 색이나 점 모양만으로 정보를 전달하지 않고 텍스트도 제공한다.
6. 정기 납입과 자유 납입을 지원한다. 정기 납입은 예정일에 자동 기록하고 사용자가 사후 수정할 수 있도록 설계한다.
7. 은행 연동 없이 생성한 자동 기록을 실제 이체가 확인된 것으로 표현하지 않는다.

## 2. 메뉴와 화면 구조

메뉴 선택이 보기 방식보다 상위에 오도록 구성한다.

```text
가계부                  저축                  일정
────────────────────────────────────────────────
선택한 메뉴의 보기 전환: 목록 / 달력
월 이동: 이전          2026년 10월          다음 · 오늘
────────────────────────────────────────────────
월 요약 / 목록 또는 달력
```

- 기존 가계부의 수입/지출 내역과 고정 수입/지출 기능은 유지한다.
- 저축 첫 진입은 목록으로 한다. 이후 보기 선택 유지 여부는 아래 추가 결정 항목으로 둔다.
- 달력의 기존 통합 조회는 유지하는 방향으로 설계한다. 통합 조회에서는 저축도 구분해 표시하고, 저축 메뉴의 달력에서는 저축만 표시한다.
- 통합 달력 진입 위치와 기존 전체/가계부/일정 필터의 재배치는 현재 화면 구조 확인 후 확정한다. 기존 통합 조회 기능을 메뉴 개편 과정에서 없애지 않는다.

## 3. 저축 목록

### 월 요약

- 선택한 월의 납입 합계와 인출 합계를 구분한다.
- 순납입액은 납입 − 인출로 계산한다.
- 미래 예정 금액을 납입 합계에 섞지 않는다. 필요하면 별도의 ‘납입 예정’ 금액으로 표시한다.
- 누적액에는 기준 시점을 명시한다. 제안: 과거 월은 해당 월말, 현재 월은 오늘까지의 기록을 기준으로 계산한다.
- 계좌 연동 잔액이 아니므로 ‘기록 기준 저축액’이라는 의미를 유지한다.

### 저축 항목 카드

- 상품/목표 이름: 예) 청년 적금, 여행 자금, 비상금
- 종류: 정기 납입 / 자유 납입
- 누적 저축액
- 정기 항목은 월 납입액과 다음 납입 예정일
- 목표 금액이 있으면 목표 대비 진행률
- 만기일이 있으면 만기일 표시
- 카드를 누르면 상세 화면에서 설정과 납입·인출 이력을 확인한다.

목록에 미래에 시작하거나 이미 종료된 항목을 어떻게 표시할지는 월 기준 활성 여부와 함께 결정한다. 월을 바꿨는데 모든 카드가 현재 기준으로만 표시되어 혼동되는 상황을 피한다.

## 4. 생성·수정 및 내역 입력

### 저축 항목 설정

| 필드 | 내용 |
| --- | --- |
| 이름 | 필수. 상품 또는 목표 이름 |
| 납입 방식 | 정기 / 자유 |
| 정기 금액 | 정기 선택 시 필수, 양수 원 단위 |
| 첫 납입 예정일 | 정기 선택 시 필수 |
| 자동 반영 시작일 | 제안: 오늘 기본값, 과거 날짜 허용 |
| 주기 | 초기 범위는 매월을 제안 |
| 만기일 | 선택. 입력 시 시작일 이전일 수 없음 |
| 목표 금액 | 선택, 양수 |
| 메모 | 선택 |

정기 설정이 없는 자유 저축도 수동 납입·인출을 기록할 수 있다. 실제 은행 계좌번호와 인증 정보 수집은 초기 범위에 포함하지 않는다.

### 납입·인출 기록

- 날짜, 금액, 납입/인출 구분, 납입자, 메모를 기록한다.
- 공동 공간에 속한 항목으로 관리하고 작성자와 납입자는 필요에 따라 구분한다.
- 금액 입력은 기존 가계부와 동일하게 사람이 읽기 쉬운 금액 표기와 `+1천 / +1만 / +5만 / +10만` 버튼을 제공한다.
- 이미 반영된 기록의 금액·날짜를 수정할 수 있다.
- 자동 기록에는 ‘자동 반영’ 표시를 제공한다. 실제 은행 이체 완료를 의미하는 문구는 사용하지 않는다.

## 5. 달력 및 drawer

### 표시 규칙

| 대상 | 표현 |
| --- | --- |
| 저축 기본 색 | `#0D9488` |
| 저축 강조 배경 | `#F0FDFA` |
| 미래 납입 예정 | 청록색 빈 점 |
| 반영된 납입 | 청록색 채운 점 |
| 저축 인출 | 저축 색상 유지, 상세에서 ‘인출’과 금액을 명시 |

- 달력에 저축 범례를 제공한다.
- 한 날짜에 항목이 많으면 점을 무제한 늘리지 않고 건수/더 보기로 요약한다.
- 같은 회차가 예정과 기록으로 중복 표시되지 않도록 한다.
- 빈 점/채운 점에는 스크린리더가 이해할 수 있는 상태 이름을 제공한다.
- 만기일을 달력에 별도 표시할지는 추가 결정 항목이다. 납입 예정으로 오인되지 않게 한다.

### 날짜 선택 drawer

- 선택 날짜와 저축명, 금액, 납입자, ‘납입 예정 / 납입 기록 / 인출 기록’을 표시한다.
- 예정 항목과 반영된 내역은 동작을 구분한다. 예정은 정기 설정 확인, 기록은 상세·수정으로 연결한다.
- 항목이 길어도 내부 스크롤을 유지한다.
- 상단 핸들을 아래로 끌어 닫는 기존 동작을 유지한다. X 버튼은 추가하지 않는다.
- 바닥 안전 영역과 배경 스크롤 잠금을 적용한다.

## 6. 가계부 집계와의 관계

저축의 원금 이동을 수입·소비 지출로 집계하지 않는다.

| 행동 | 가계부 | 저축 |
| --- | --- | --- |
| 월급 300만 원 입금 | 수입 +300만 원 | 변화 없음 |
| 생활비 100만 원 지출 | 지출 +100만 원 | 변화 없음 |
| 적금에 50만 원 납입 | 수입·지출 합계 변화 없음 | 납입 +50만 원 |
| 원금 20만 원 인출 | 수입·지출 합계 변화 없음 | 인출 +20만 원 |
| 이자 1만 원 수령 | 수입 +1만 원 | 이자 처리 방식은 별도 결정 |

- 기존 ‘월 차액 = 수입 − 지출’은 유지한다.
- 저축을 차감한 값을 실제 계좌 ‘잔액’으로 부르지 않는다.
- 가계부에서 이번 달 저축을 참고용으로 보여주더라도 수입·지출 합계와 분리한다.
- 기존 지출에 등록된 적금 항목을 자동 변환하지 않는다. 이전 시 중복 집계를 막는 절차가 필요하다.

## 7. 자동 반영 설계 제안

기존 고정 수입/지출의 경험을 반영한 제안이며, 아래 세부 정책은 구현 전 확정한다.

- 한국 시간 날짜를 기준으로 납입 예정일이 도래하면 저축 기록을 생성한다.
- 등록·설정 수정 직후 즉시 반영하고, 주기 작업은 누락 보완용으로 유지한다.
- 항목과 회차를 식별하는 키로 재시도·동시 실행 시 중복 생성을 막는다.
- 과거 시작일이면 적용 범위 안의 도래한 회차를 생성한다. 미래 회차는 예정으로만 표시한다.
- 29~31일이 없는 달에는 해당 월 말일에 납입하는 방식을 제안한다. 다음 달에는 원래 설정일을 기준으로 돌아간다.
- 설정 변경으로 과거 회차가 바뀌는 경우 추가·삭제될 내역을 미리 보여준다.
- 사용자가 직접 수정한 기록은 보존한다. 자동 생성한 미수정 기록만 재조정 대상으로 삼는다.
- 사용자가 삭제한 자동 회차가 다음 배치에서 다시 생성되지 않도록 삭제 의도를 보존한다.
- 만기 이후에는 새 예정·자동 기록을 생성하지 않는다. 만기일 당일 납입 포함 여부는 확정이 필요하다.

## 8. 모바일·PWA 및 접근성

- 앱의 기존 인디고 탐색/주요 버튼 체계를 유지하고, 청록색은 저축 데이터의 의미를 표시하는 데 사용한다.
- 청록색 텍스트·아이콘·점의 대비를 실제 배경에서 검증한다. 작은 텍스트는 필요 시 더 진한 청록색을 사용한다.
- 모바일 터치 영역과 좁은 화면의 메뉴 너비를 확인한다.
- 모달 제목과 닫기 버튼은 고정하고 입력 영역만 스크롤한다. 기존 입력 영역의 자연스러운 스크롤 감각을 유지한다.
- 하단 요소에 `safe-area-inset-bottom`을 반영하고 overlay에서 body 스크롤을 잠근다.
- 아이콘은 lucide-react, 선택 입력은 공통 Select를 사용한다.
- 한글 IME 입력 중 Enter 중복 제출을 방지하고 저장 중 중복 요청을 막는다.

## 9. 초기 구현 범위와 제외 범위

### 초기 범위 제안

- 동일 계층 저축 메뉴와 월별 목록/달력
- 정기·자유 저축 생성, 수정, 조회
- 납입·인출 기록과 누적 집계
- 매월 자동 반영 및 사후 수정
- 공유 공간 권한과 공동 사용자 화면 갱신

### 초기 제외

- 은행 연동, 실제 자동 이체 실행·입금 확인
- 투자 상품 평가손익, 환율, 세금 계산
- 이자·만기 수령액 자동 계산
- 기존 가계부 데이터의 일괄 자동 변환

## 10. 구현 전 추가 결정 항목

1. 메뉴 개편 이후 통합 달력의 진입 위치와 기존 필터 구성
2. 저축 목록/달력 마지막 선택 및 월 선택 유지 범위
3. 기존 저축의 시작 잔액 입력 지원 여부 — 과거 납입 이력이 없는 기존 적금 대응
4. 누적액을 넘는 인출의 처리 방식
5. 만기 당일 납입 포함 여부와 종료·해지·항목 삭제 정책
6. 자동 반영 시작일과 첫 납입 예정일의 구분을 그대로 적용할지
7. 이자를 저축에 남기는 경우 원금·이자·가계부 수입의 중복 없는 연결 방식
8. 목표 기반 저축에서 납입자 선택 및 기본값 정책

위 항목은 미확정 상태다. 구현 시 임의로 은행 잔액이나 이체 확인을 추정하지 않는다.

## 11. 완료 검증 기준

- 가계부·저축·일정을 같은 계층에서 이동할 수 있다.
- 저축의 목록/달력 및 월 이동이 같은 기준의 데이터를 보여준다.
- 납입·인출이 저축 집계에는 반영되고 기존 수입·지출 합계에는 섞이지 않는다.
- 미래 예정과 반영된 내역을 상태·모양·텍스트로 구분한다.
- 정기 회차의 즉시 생성, 중복 실행, 월말, 과거 시작일, 사후 수정, 삭제 후 재생성을 검증한다.
- 같은 공유 공간의 다른 사용자가 변경된 저축 기록을 확인할 수 있고 다른 공간에는 접근할 수 없다.
- iOS PWA에서 긴 모달·drawer 스크롤과 닫기, 안전 영역, 한글 입력 및 금액 버튼을 확인한다.
- 개발 완료 후 별도로 리뷰·테스트·배포 상태를 확인한다. 이 기획서 저장은 구현 또는 배포 완료를 뜻하지 않는다.

## 12. 구현 시 확정한 초기 정책 (2026-10-18)

- 생활 관리 메뉴를 상위로 이동하고, 통합 달력은 보기 전환 영역에서 별도로 진입한다. 기존 통합 조회를 유지한다.
- 저축 메뉴 진입은 목록으로 시작한다. 보기 상태는 현재 화면에서만 유지하며 영구 저장하지 않는다.
- 현재/미래 월의 누적액은 오늘까지, 과거 월은 월말까지 계산하고 기준 날짜를 표시한다. 항목 설정 카드와 다음 납입일은 현재 설정 기준임을 표시한다.
- 시작 잔액 전용 필드는 추가하지 않는다. 기존 잔액은 수동 납입 기록과 메모로 입력할 수 있다.
- 과거 기록을 일부만 입력한 계정도 사용할 수 있도록 누적액을 넘는 인출을 허용한다. 이 경우 기록 기준 누적액은 음수가 될 수 있으며 은행 잔액으로 표현하지 않는다.
- 만기 당일 회차까지 포함한다. 저축 종료는 이후 자동 납입을 중지하고 과거 기록을 보존한다. 기록 자체의 수정·삭제는 종료 후에도 가능하다.
- 자동 반영 시작일 기본값은 오늘이다. 첫 예정일과 자동 반영 시작일 중 늦은 날부터 회차를 생성한다.
- 자동 회차의 식별 기준은 항목 ID와 예정 월이다. 날짜를 직접 수정해도 동일 회차를 새로 생성하지 않는다.
- 같은 공유 공간 멤버를 납입자로 선택한다. 처음 생성 시 멤버 목록의 첫 사람을 기본값으로 표시하고 변경할 수 있다.
- 이자 자동 계산·저축/가계부 동시 기록은 제외한다. 이자는 기존 가계부 수입으로 별도 입력한다.
- 공동 사용자의 변경은 앱 복귀·포커스 및 화면이 보이는 동안 60초 주기로 재조회한다. 실시간 소켓 기능은 추가하지 않는다.
- 예정 항목은 설정 수정으로, 실제 납입·인출은 기록 수정으로 연결한다. 달력에서 기록 추가를 누르면 저축 목록에서 해당 항목을 선택한다.
- 배포 시 백엔드의 `scripts/add-savings.sql`을 먼저 적용해야 한다. 운영 DB는 `ddl-auto=validate`이므로 앱 시작만으로 테이블을 만들지 않는다.

## 13. 사용자 피드백 반영 (2026-10-18)

이 절이 이전 메뉴 순서·기본 보기·색상 결정보다 우선한다.

- 상단: 달력 / 목록. 하단: 전체 / 가계부 / 저축 / 일정.
- 보기와 항목 필터는 독립적이다. 저축을 선택해도 목록으로 이동하지 않고, 목록을 선택해도 가계부로 바뀌지 않는다.
- 통합 달력을 별도 보기로 취급하지 않는다. ‘전체 + 달력’과 ‘전체 + 목록’을 모두 지원한다.
- 전체 목록은 가계부·저축·일정을 날짜순으로 함께 표시한다.
- 저축 색상은 수입의 초록색과 구분하기 위해 amber 계열로 변경한다. 점/아이콘 `#D97706`, 텍스트 amber-700, 배경 amber-50을 사용한다.
- 예정은 빈 점, 기록은 채운 점 규칙은 유지한다.
